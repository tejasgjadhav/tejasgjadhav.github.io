A working model of how an agent that "remembers nothing" ends up behaving as if it does.
[[tejas-jadhav]] uses his own setup as the example and teaches it as a slide in Module 1 of
the [[aifinance]] course. The load-bearing point is at the bottom: the model itself carries
nothing between calls. Every layer below is a file that somebody maintains.

**1. Session chat — short-term memory.** Whatever has been said in the current
conversation. It disappears, or is compressed to a summary, when the session ends. Nothing
survives unless it gets written to a file.

**2. Auto-memory — episodic memory.** One small file per fact, plus an index that loads at
the start of every session. These are facts about the person and the work: which city an
employer is in, when a scraper runs, what not to do on a résumé. The model writes them; the
user rarely edits them by hand, they just say "remember this". This is **not** the rulebook.

**3. `CLAUDE.md` — the rulebook, not memory.** Standing instructions about how to behave:
check the policy before acting, keep answers short, make surgical edits. It loads verbatim
every session. If auto-memory is the employee's notebook, this is the employee handbook —
which is also the answer to "where do I add a new instruction?": behaviour goes here, facts
go in layer 2.

**4. The wiki — semantic memory, and the user's rather than the model's.** This wiki: notes,
sources, project pages, durable answers. It exists to be queried, not to instruct the model.
See [[files-repo]].

A fifth thing, sitting across layers 2 and 4, is the **link graph**. Both the auto-memory
files and these pages cross-reference each other with double-bracket wikilinks, so both can be drawn
as a graph — 54 memory files and 73 links as of 2026-08-08. Rendering it is how orphaned
notes and broken links become visible; the wiki's own view is generated by
`tools/build_graph.py` and never hand-edited.
